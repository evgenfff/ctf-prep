# 09. Команда: роли, связь, договорённости

Победа на Кубке — это не сумма скиллов, а **организация**. Команда из 7 средних игроков с ролями и дисциплиной обходит команду из 5 звёзд без координации.

---

## 1. Состав и роли

### 1.1. Капитан
**Отвечает за:**
- регистрацию и переписку с оргкомитетом;
- состав и замены;
- таймлайн и распределение задач;
- отправку флагов и апелляции;
- получение приза и его распределение;
- финальное решение в спорных ситуациях.

**Не делает:**
- не берёт сложную задачу на 4 часа;
- не уходит в глубокий реверс;
- не спорит о технике — фиксирует решение и идёт дальше.

**Качества:** дисциплина, трезвая оценка времени, умение сказать «стоп».

### 1.2. Заместитель капитана
- Ведёт команду, когда капитан спит (02:00–06:00).
- Дублирует доступы к платформе.
- Следит за таблицей задач.
- Может отменить решение капитана, если тот не в состоянии.

### 1.3. Технические роли

| Роль | Отвечает | Вторая зона |
|---|---|---|
| Web | web, API, auth | osint |
| Pwn | pwn, binary | reverse |
| Crypto | crypto, math | misc |
| Reverse | reverse, mobile | pwn |
| Forensics | forensics, malware | misc |
| Универсал | ppc, misc, помощь | любая |

**Правило:** у каждой задачи один владелец. Помогать могут все, но ответственность — на владельце.

### 1.4. Матрица RACI

| Задача | Капитан | Владелец | Все |
|---|---|---|---|
| Регистрация | A/R | C | I |
| Выбор задач | A | C | I |
| Решение задачи | I | A/R | C |
| Отправка флага | A | R | I |
| Патч в AD | A | R | C |
| Связь с оргкомитетом | A/R | I | I |
| Приз | A/R | C | I |

`A` — accountable, `R` — responsible, `C` — consulted, `I` — informed.

## 2. Варианты состава

### 5 человек (минимум для академического/смешанного)
1. Капитан + web.
2. Pwn.
3. Crypto.
4. Reverse.
5. Forensics + misc.

**Риск:** если один выпадает, зона пустует. Нужны «вторые» навыки у каждого.

### 6 человек
1. Капитан (координация + быстрые флаги).
2. Web.
3. Pwn.
4. Crypto.
5. Reverse.
6. Forensics + misc.

**Оптимально:** капитан свободен для триажа и помощи.

### 7 человек
1. Капитан.
2. Web-1.
3. Web-2 (+ osint).
4. Pwn.
5. Crypto.
6. Reverse.
7. Forensics + misc + ppc.

**Плюс:** можно закрыть две задачи параллельно в каждой зоне.
**Минус:** больше координации; нужен чёткий канал.

## 3. Связь

### 3.1. Каналы
| Канал | Назначение | Правила |
|---|---|---|
| `#general` | оргвопросы, время, платформа | только по делу |
| `#web`, `#pwn`, `#crypto`, `#rev`, `#for`, `#misc` | рабочие обсуждения | контекст, файлы, гипотезы |
| `#flags` | факты отправки флагов | без обсуждений |
| `#help` | просьбы о помощи | шаблон + таймаут |
| Голос | стендапы, критическое | не для фонового шума |

### 3.2. Шаблон сообщения о помощи
```text
Задача: <name>
Категория: <cat>
Что делаю: <действие>
Ожидал: <результат>
Факт: <результат/ошибка>
Что проверил: <список>
Файлы: <пути>
Нужно: <конкретно>
```

### 3.3. Стендап каждые 90 минут
```text
1. Решено: ...
2. В работе: ... (ETA)
3. Блок: ... (нужна помощь)
4. Следующее: ...
```
5 минут, не больше. Капитан записывает решения.

### 3.4. Правила общения
- Критикуйте идею, а не человека.
- Не перебивайте, пока человек не закончил мысль.
- Если не согласны — предложите альтернативу.
- После решения капитана не обсуждайте его в общем чате.
- Личные конфликты — после контеста.

## 4. Договор о призе

**Зафиксируйте до старта, письменно, в чате.**

Шаблон:
```text
Команда: <название>
Зачёт: <академический/смешанный/...>
Приз: 250 000 ₽, включая НДФЛ 13%.
Получатель: капитан <ФИО>.
Распределение: равными долями между <N> участниками, участвовавшими в финале.
Расчёт: (250 000 - 13%) / N.
Если участник не приехал на финал: <решение>.
Если участник покинул команду: <решение>.
Налоги: удерживаются из суммы, капитан переводит доли.
Срок перевода: <X> дней после получения.
Споры: решает капитан, либо <арбитр>.
```

**Почему это важно:** после победы начинаются споры «кто сколько вложил». Договор снимает 90% проблем.

## 5. Дисциплина и античит

### Разрешено
- Любые инструменты, не атакующие инфраструктуру.
- Чтение документации, writeup'ов прошлых лет.
- Автоматизация, скрипты, LLM — **если разрешено положением**.

### Запрещено
- Атаки на платформу, жюри, сети организаторов.
- Атаки на другие команды.
- Обмен флагами и решениями.
- Саботаж.
- Использование чужих флагов.
- Нарушение возрастных/организационных требований.

### Последствия
- Дисквалификация команды.
- Аннулирование результатов.
- Возможный бан на будущие турниры.

**Правило:** сомневаешься — спроси капитана, капитан — оргкомитет. Не решай в одиночку.

## 6. Замены и форс-мажоры

| Ситуация | Действие |
|---|---|
| Участник заболел | Замена до финала — через оргкомитет; на отборе — перераспределить задачи |
| Пропал интернет | Резервный канал; продолжить с телефона |
| Сломался ноутбук | Резервное устройство; данные — в git/облаке |
| Участник выгорел | 2 часа сна; капитан перераспределяет |
| Конфликт | Капитан фиксирует решение; обсуждение после |
| Дисквалификация | Капитан выясняет причины; команда продолжает |

**Правило замены:** новый участник должен соответствовать зачёту и быть согласован с оргкомитетом **до** финала.

## 7. Личные данные и документы

- Паспортные данные, согласия, справки — только в `admin/`, не в общем чате.
- Капитан хранит копии в защищённой папке.
- Не отправляйте документы в публичные каналы.
- После турнира удалите лишние копии.

## 9. Принятие решений

### В отборе
- Капитан решает, какую задачу брать.
- Владелец решает, как решать.
- Если владелец застрял > 60 минут — капитан передаёт задачу или паркует.

### В AD
- Service owner решает, что патчить.
- Капитан утверждает патч, если он меняет API.
- Attacker не трогает сервис без согласования.

### В секретном финале
- Владелец машины решает тактику.
- Капитан собирает куски ключа и координирует.
- Если машина стоит > 45 минут — свободный охотник подключается.
